# Beta QA round, 30 September 2026

A round against one real group, run across three devices: the iPhone 18 Pro Max simulator and the Pixel 10 (Android
17) emulator sharing a group over a local reference server, and the owner's own iPhone 18 Pro Max on TestFlight
against the real server. "How the environment was run" below has the setup and its pitfalls.

## Setup

| | |
|---|---|
| Group | "Banff 2026", CAD, shared by the simulator and the emulator |
| iPhone 18 Pro Max simulator | Debug build, local reference server |
| Pixel 10 emulator (Android 17) | Debug build, local reference server |
| Owner's iPhone 18 Pro Max | TestFlight builds 129–131, real server |

The simulator and the emulator reached the same local reference server, at the Mac's LAN address, so a push from
either side showed up on the other. The phone ran the TestFlight builds against the production server instead, so
its results are listed separately where the two environments diverge.

## What passed

The owner reported everything below as good; nothing here needed a second look.

- Sync both ways between the simulator and the emulator.
- The notification ask on both platforms, including the Android fix verified on the emulator: Back on the prompt
  is asked again on the next qualifying open, two closes in a row leave the switch reading off but the group screen
  quiet, and the switch then opens Settings instead of a prompt.
- The invite link and its QR display.
- The "You're already in" preview (canvas v36, JoinCodeHeld) for a held group's invite.
- The Split extra chip growing to fit its amount instead of showing a lone "+".
- The themed Android system dialog ("Delete this expense?" and the error alerts), dressed in Even's surface, type
  and accent.
- Three-button navigation on Android with the canvas showing through, no contrast band.
- Largest text sizes, both platforms: Cancel and Done keep their full width, the sheet title gives way.
- Diagnostics on both platforms, with Android's page leaving out the model sections (no on-device model there).
- Report and Help opening the contact page: a Chrome Custom Tab on Android, the in-app browser on iOS.
- On the phone specifically: the universal link with Even in the background and with Even in the foreground, and
  the "You're already in" preview reached from a link rather than a pasted or scanned code.

## Bugs found this round

Each was found during the round and fixed the same day; commits are on `main`.

| Bug | Fix |
|---|---|
| An invite link that reached a running Even landed on Groups with no Join preview, instead of opening Join | `7077130` — routes the link through expo-router's native intent (`+native-intent.ts`) instead of a `useURL()` subscription that missed events that arrived after a screen had mounted |
| No "already in" state: an invite for a group the phone already held previewed like any other invite and opened the group without saying so | `ebef94d` — adds the JoinCodeHeld preview from canvas v36 ("You're already in", Open) |
| The Split extra chip clipped to a lone "+" instead of showing the amount | `b23c062` — the chip now grows to fit its text instead of a fixed 72 pt field that could only show up to the first line break |
| An Android notification prompt closed with Back was read as a permanent refusal, so the app never asked again | `b59615f` — a closed prompt now counts as no answer for the first two tries before the app treats it as a refusal and defers to Settings |
| The dev server's database lived inside the repo, so every sync push triggered a Metro fast refresh | `89ca038` — moves the dev server's database out of the repo (`EVEN_DEV_SERVER_DATA`, default `~/Library/Caches/even-dev-server`) and blocks `.dev/` in Metro's resolver as a backstop |

Two more are in progress on the `ios-transition-and-join-keyboard` branch, not yet landed on `main`:

- The Join with code sheet's keyboard covers the "You're already in" preview (keyboard dismissal needs more work).
- A light rim/underlay shows behind the rounded-card transition in dark mode on iOS 27.

## Not verified

- A real QR scan with a camera: no device in this round had one (the simulator and the emulator both show a
  virtual scene).
- Background refresh delivering a notification, on the phone or on the emulator. This needs a wait the round did
  not include; nothing here confirms it works, and nothing in the git log or from the owner says otherwise.
- Android App Links. The debug build's domain is unverified, so the link opened Chrome instead of Even; this is a
  property of the Debug build's signing, not the native-intent fix in `7077130`.
- OEM skins (Samsung, Xiaomi, OnePlus, etc.); only the stock Pixel system was checked, as in the earlier Android
  review.
- The sync-push delay seen under the Android permission dialog. `b59615f`'s commit message explains it: JS timers
  pause while the dialog is up, so a push queued during it is only delayed, not lost — latency only, not a bug.

## How the environment was run

- The dev server was bound to the Mac's LAN address rather than localhost, so both the simulator and the emulator
  pointed at the same `https://192.168.1.98:8787`; Debug builds speak plain HTTP to private addresses, so this
  worked without a certificate.
- One Metro instance served both devices.
- The shared group's invite was made from the dev seed's fixed key, so the simulator and the emulator joined the
  same group rather than each seeding its own.

Pitfalls to keep in mind for the next round:

- Never open a seed link on a device that already shares the server: it deletes the shared group's copy on that
  device.
- Don't restart the dev server mid-round. Its database is emptied on restart, taking the shared group with it.
- The App Link path needs "Open supported links" turned on for the debug install before an Android link will open
  Even instead of Chrome.
